Phase 1 — Conformité FNE/DGI : certification, sticker QR, pré-validation, tests

- FneService : certification via l'API FNE avec mock intégré fidèle au contrat
  DGI (endpoint /sign, auth Bearer, mêmes erreurs 400, numéro fiscal officiel
  {NCC}{AA}{séquence}, token de vérification, solde de stickers). Bascule
  simulation -> réel par simple configuration (URL + clé API), sans code.
- Pré-validation en français avant tout envoi : regroupe les exigences DGI
  manquantes (téléphone/email client, point de vente, lignes...) en un message
  clair ; lève ValidationError sans marquer la facture en erreur.
- QrCode : générateur de QR en code pur, sans dépendance (byte mode, EC niveau M,
  versions 1-10, masquage optimal). Vérifié par décodage réel (jsqr).
- PdfService : bandeau de certification en pied de facture (visuel FNE neutre,
  numéro fiscal, QR). Mode simulation explicitement marqué « NON OPPOSABLE ».
- UI : colonne/action FNE côté factures + section Paramètres FNE.
- Schéma : colonnes numeroFiscal, fneToken, fneStatut, fneInvoiceId (migration
  douce via initialiserApplication).
- Tests : suite Node (vm + stubs GAS) — 95 assertions (FNE, décodage QR, bandeau).
- Build : build.sh génère la « version facile » build/Code.gs (fusion ordonnée).
- README : statut de conformité FNE (POC non certifié), tests, roadmap à jour.

POC fonctionnel mais NON certifié : les factures produites ne sont pas
légalement opposables tant que l'enrôlement officiel DGI n'est pas réalisé.
